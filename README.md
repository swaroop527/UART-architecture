# UART Architecture

There are 4 modules and 1 top module in this project:

* Receiver
* Transmitter
* Baud Generator
* Debouncer

### (a) Baud Generator

**Inputs:**

* `clock`
* `reset`

**Output:**

* `baud_tick`

This module divides the input time into 16 parts. Every time `baud_tick` gets high, it stays high for 1 clock cycle. Why 16 parts? This is because we can read a stable input at the 8th `baud_tick`, and it is also far away from either of the transition edges of the input.

We are taking a baud rate of **9600** here, which means there are 9600 bits received by the device per second.

So `baud_tick` gets high **9600 × 16 = 153600 times every second**.

There are approximately:

`clock frequency / (16 × 9600)`

clock periods between two consecutive `baud_tick` pulses. With a clock frequency of 100 MHz, this requires a register that counts approximately **651 clock cycles** before `baud_tick` becomes high.

### (b) Receiver

**Inputs:**

* `clock`
* `reset`
* `baud_tick`
* `rx_serial`

**Outputs:**

* `rx_data` (8 bits wide)
* `rx_valid`

This module is meant to receive 1 bit at a time via `rx_serial` and generate a byte over time.

`rx_serial` is ideally high. When something needs to be sent to the device, it goes low for the start bit. Then the whole byte is transferred bit by bit.

When the byte is ready, `rx_valid` is held high for 1 clock cycle.

This is programmed as an FSM.

### (c) Transmitter

**Inputs:**

* `clock`
* `reset`
* `baud_tick`
* `tx_start`
* `tx_data` (8 bits)

**Outputs:**

* `tx_busy`
* `tx_serial`

This module takes the byte generated by the UART device and sends each bit via `tx_serial`.

`tx_start` tells this module that a byte is incoming.

When `tx_busy` is high, it basically tells that the transmitter module is busy with the present byte.

### (d) Debouncer

**Inputs:**

* `clock`
* `reset`
* `btn_raw`

**Output:**

* `btn_clean`

This module is meant to process the physical push button on the FPGA or UART device, which allows the computer to receive the processed data.

It reads `btn_raw`, and when it receives a stable input for **10 ms**, it makes `btn_clean` high for 1 clock cycle.
